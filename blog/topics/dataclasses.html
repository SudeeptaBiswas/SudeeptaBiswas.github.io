Dataclasses vs Java records

A Java record gives you a constructor, accessors, equals, hashCode and toString. Python's @dataclass builds the same from a list of fields. The big difference: dataclass fields can change, unless you ask for frozen=True.

record Message(String role, String content) {}

var m1 = new Message("user", "hi");
var m2 = new Message("user", "hi");
m1.equals(m2);      // true
m1.toString();      // Message[role=user, content=hi]
m1.role();          // accessor; there is no setter

The basics

from dataclasses import dataclass, field

class PlainMessage:                          # plain class: no __eq__ written
    def __init__(self, role, content):
        self.role = role
        self.content = content

@dataclass
class Message:                               # __init__, __repr__, __eq__ for free
    role: str
    content: str
    tags: list[str] = field(default_factory=list)

print("plain equal:    ", PlainMessage("user", "hi") == PlainMessage("user", "hi"))
m1 = Message("user", "hi")
m2 = Message("user", "hi")
print("dataclass equal:", m1 == m2)
print(m1)

m1.tags.append("greeting")
print("m2.tags:", m2.tags)                   # each object got its own list

m1.content = "changed"                       # fields can change (records can't)
print(m1)
print(Message(role=1, content=None))         # type hints are not checked

Output:

plain equal:     False
dataclass equal: True
Message(role='user', content='hi', tags=[])
m2.tags: []
Message(role='user', content='changed', tags=['greeting'])
Message(role=1, content=None, tags=[])
  • A plain class compares by identity, like a Java class without equals().
  • Type hints are not checked when the code runs: role=1 is accepted. pydantic, later in the lab, does check.

frozen=True: closest to a record

from dataclasses import FrozenInstanceError, dataclass, replace

@dataclass(frozen=True)
class Settings:                              # like a Java record: no setters
    model: str
    temperature: float = 0.8

s = Settings("qwen3:1.7b")
print(s)
try:
    s.temperature = 0.2
except FrozenInstanceError as error:
    print("FrozenInstanceError:", error)

cold = replace(s, temperature=0.2)           # a changed copy ("wither")
print(cold)
print(s)                                     # the original is unchanged
print("usable as a dict key:", {s: "default"}[Settings("qwen3:1.7b")])

Output:

Settings(model='qwen3:1.7b', temperature=0.8)
FrozenInstanceError: cannot assign to field 'temperature'
Settings(model='qwen3:1.7b', temperature=0.2)
Settings(model='qwen3:1.7b', temperature=0.8)
usable as a dict key: default

Frozen also makes it hashable, so it can be a dict key or go in a set.

The list default trap

tags: list = [] would give every object the same list, so @dataclass refuses it:

from dataclasses import dataclass

try:
    @dataclass
    class Bad:
        tags: list = []                      # one list for every object? refused
except ValueError as error:
    print("ValueError:", error)

Output:

ValueError: mutable default <class 'list'> for field tags is not allowed: use default_factory

Use field(default_factory=list): a new list for each object, as in Message above. The same trap in plain functions: Python traps for Java developers.
