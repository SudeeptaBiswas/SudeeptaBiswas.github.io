Cosine similarity

An embedding turns a text into a list of numbers, a vector. Texts with similar meaning get vectors that point the same way. Cosine similarity measures how alike two directions are: 1 same, 0 unrelated, -1 opposite.

Arrows on a map

Real embeddings have 768 numbers. With two numbers, [about animals, about money], you can draw them:

TextVectorPoints
animal[0.9, 0.1]east
kitten[0.8, 0.2]nearly the same way
invoice[0.1, 0.9]north

The formula

dot(a, b)    = a0*b0 + a1*b1 + ...                 (Java: a for loop)
norm(a)      = sqrt(dot(a, a))                     (arrow length, Pythagoras)
cosine(a, b) = dot(a, b) / (norm(a) * norm(b))

Why divide by the lengths? A long note and a short note about the same thing point the same way but have different lengths. dot grows with length; cosine doesn't.

Step by step

Question "a small pet" = [0.7, 0.3], note "kitten" = [0.8, 0.2].

  1. dot: multiply the numbers in the same position, then add. 0.7×0.8 + 0.3×0.2 = 0.56 + 0.06 = 0.62. In Java: for (int i = 0; i < a.length; i++) sum += a[i] * b[i]; It is big when both arrows point the same way, but also when they are long.
  2. norm: the length of one arrow, by Pythagoras: √(x² + y²). Question: √(0.49 + 0.09) = √0.58 = 0.762. Kitten: √(0.64 + 0.04) = √0.68 = 0.825. With 768 numbers it is the same: square all 768, add, take the square root. sqrt(dot(a, a)) is that sum of squares, reused.
  3. cosine: dot divided by both lengths, so only the direction is left. 0.62 / (0.762 × 0.825) = 0.62 / 0.629 = 0.99.

It is called cosine because the result is the cosine of the angle between the two arrows. The question points 23° up from "animals", kitten 14°: 9° apart, and cos 9° = 0.99. Same arrow direction gives 1 (0°), a right angle gives 0 (90°), opposite gives -1 (180°).

The code

import math

def dot(a: list[float], b: list[float]) -> float:
    if len(a) != len(b):                                 # zip would silently stop at the shorter one
        raise ValueError(f"lengths differ: {len(a)} vs {len(b)}")
    return sum(x * y for x, y in zip(a, b))

def norm(a: list[float]) -> float:
    return math.sqrt(dot(a, a))                          # arrow length

def cosine(a: list[float], b: list[float]) -> float:
    return dot(a, b) / (norm(a) * norm(b))

# Two numbers per text: [about animals, about money]
notes = {"animal": [0.9, 0.1], "kitten": [0.8, 0.2], "invoice": [0.1, 0.9]}
question = [0.7, 0.3]                                    # "a small pet": mostly animal

for name, vector in notes.items():
    print(f"{name:8} cosine {cosine(question, vector):.2f}")

ranked = sorted(notes, key=lambda name: cosine(question, notes[name]), reverse=True)
print("top 2:", ranked[:2])

kitten = notes["kitten"]
long_kitten = [x * 10 for x in kitten]                   # same direction, 10 times longer
print(f"dot    animal-kitten {dot(notes['animal'], kitten):.2f}  vs long kitten {dot(notes['animal'], long_kitten):.2f}")
print(f"cosine animal-kitten {cosine(notes['animal'], kitten):.2f}  vs long kitten {cosine(notes['animal'], long_kitten):.2f}")

Output:

animal   cosine 0.96
kitten   cosine 0.99
invoice  cosine 0.49
top 2: ['kitten', 'animal']
dot    animal-kitten 0.74  vs long kitten 7.40
cosine animal-kitten 0.99  vs long kitten 0.99

Search is just this: score the question against every note, sort, keep the top k.

The same with numpy

numpy does the whole table in one line. This block loads numpy when you run it.

import numpy as np

names = ["animal", "kitten", "invoice"]
notes = np.array([[0.9, 0.1], [0.8, 0.2], [0.1, 0.9]])   # one row per note
question = np.array([0.7, 0.3])

scores = notes @ question / (np.linalg.norm(notes, axis=1) * np.linalg.norm(question))
for i in np.argsort(-scores):                            # best first
    print(f"{names[i]:8} {scores[i]:.2f}")

Output:

kitten   0.99
animal   0.96
invoice  0.49

Measured with nomic-embed-text (768 numbers per text):

  • Unrelated is about 0.3–0.45, not 0. Compare scores with each other; never hard-code "0.5 = match".
  • Love vs hate scores high: embeddings measure what a text is about, not whether it is positive or true.
  • Use the same model for notes and question. Vectors from two models give nonsense scores, with no error.
  • nomic's vectors already have length 1.0, so for them cosine equals dot.
