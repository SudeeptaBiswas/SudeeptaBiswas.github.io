Byte Pair Encoding (BPE)

A tokenizer needs a list of pieces to cut text into. BPE (Byte Pair Encoding) builds that list from text: start with single characters, find the two neighbours that appear together most often, glue them into one piece, and repeat.

The steps

  1. Start with one token per character. Spaces are tokens too.
  2. Count every pair of neighbour tokens.
  3. Merge the pair with the highest count into one new token, everywhere it appears. A tie keeps the first pair seen.
  4. Repeat from step 2. Each merge adds one piece to the vocabulary and makes the text shorter.

Worked example

Text: "the cat sat on the mat". It starts as 22 tokens, one per character. Four merges, as printed by the lab's example script:

MergeMost common pairNew tokenTokens left
1'a' + 't''at'19
2't' + 'h''th'17
3'th' + 'e''the'15
4'the' + ' ''the '13
 
after BPE: ['the ', 'c', 'at', ' ', 's', 'at', ' ', 'o', 'n', ' ', 'the ', 'm', 'at']

at came first because it appears 3 times (cat, sat, mat). Merges build on earlier ones: th + e only became possible after merge 2.

The code

def count_pairs(tokens: list[str]) -> dict[tuple[str, str], int]:
    counts: dict[tuple[str, str], int] = {}
    for left, right in zip(tokens, tokens[1:]):     # neighbours: ('t','h'), ('h','e'), ...
        counts[(left, right)] = counts.get((left, right), 0) + 1
    return counts

def merge_pair(tokens: list[str], pair: tuple[str, str]) -> list[str]:
    merged, position = [], 0
    while position < len(tokens):
        if position + 1 < len(tokens) and (tokens[position], tokens[position + 1]) == pair:
            merged.append(tokens[position] + tokens[position + 1])   # 'a' + 't' = 'at'
            position += 2                                            # both halves used up
        else:
            merged.append(tokens[position])
            position += 1
    return merged

tokens = list("the cat sat on the mat")      # 22 tokens
for merge_number in range(1, 5):
    counts = count_pairs(tokens)
    best_pair = max(counts, key=counts.get)    # highest count; a tie keeps the first seen
    tokens = merge_pair(tokens, best_pair)
    print(f"merge {merge_number}: {best_pair!r:12} -> {len(tokens)} tokens")

print("after BPE:", tokens)

Save it as bpe.py and run python bpe.py. Output:

merge 1: ('a', 't')   -> 19 tokens
merge 2: ('t', 'h')   -> 17 tokens
merge 3: ('th', 'e')  -> 15 tokens
merge 4: ('the', ' ') -> 13 tokens
after BPE: ['the ', 'c', 'at', ' ', 's', 'at', ' ', 'o', 'n', ' ', 'the ', 'm', 'at']

Java view: counts is a Map<Pair, Integer> where the pair (left, right) is a small record used as the key, and counts.get(k, 0) is getOrDefault. max(counts, key=counts.get) is a stream's max(comparing(counts::get)).

Why it matters

  • No unknown words. A word the tokenizer never saw is still cut into smaller known pieces, down to single characters if needed.
  • Common words become one token, rare words several. That is why 1 token is about 4 characters of English, and why other languages and code often need more tokens.
  • Real tokenizers run tens of thousands of merges on huge amounts of text. qwen3's vocabulary has 151,936 tokens.
