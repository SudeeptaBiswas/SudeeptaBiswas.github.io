Python traps for Java developers

Python reads like Java with less typing. These five spots behave differently, and they fail quietly: no compile error, just a wrong value. Each block runs in your browser; change it and run it again.

1. / and //

/ always gives a float. // rounds down, not toward zero, so negative numbers give a different answer than in Java.

print("7 / 2   =", 7 / 2)          # / always gives a float
print("7 // 2  =", 7 // 2)         # // rounds down
print("-7 // 2 =", -7 // 2)        # down means -4; Java's -7 / 2 is -3
print("int(-7 / 2) =", int(-7 / 2))  # cut toward zero, like Java
print("-7 % 2  =", -7 % 2)         # Java's -7 % 2 is -1
print("2 ** 100 =", 2 ** 100)      # no overflow: int grows as needed

Output:

7 / 2   = 3.5
7 // 2  = 3
-7 // 2 = -4
int(-7 / 2) = -3
-7 % 2  = 1
2 ** 100 = 1267650600228229401496703205376

Porting Java maths that can go negative? Check every / and %.

2. == and is

Java's == on objects asks "same object?" and .equals() asks "same value?". Python uses == for the value and is for the same object.

a = [1, 2, 3]
b = [1, 2, 3]
c = a                              # a second name for the same list

print("a == b:", a == b)           # same value     (Java: a.equals(b))
print("a is b:", a is b)           # same object?   (Java: a == b)
print("a is c:", a is c)

c.append(4)
print("a after c.append(4):", a)   # one list, two names

x = None
print("x is None:", x is None)     # test for None with "is"

Output:

a == b: True
a is b: False
a is c: True
a after c.append(4): [1, 2, 3, 4]
x is None: True

Use is only for None (and True / False).

3. Truthy and falsy

if x: works on any value. Zero and empty things count as false.

for value in [0, 0.0, "", [], {}, None, "0", [0], -1]:
    print(f"{value!r:5} -> {bool(value)}")

count = 0                          # a real answer: zero items
if count:
    print("got a count")
else:
    print("if count: says no count, but 0 was a real value")
if count is not None:
    print("if count is not None: says the count is", count)

Output:

0     -> False
0.0   -> False
''    -> False
[]    -> False
{}    -> False
None  -> False
'0'   -> True
[0]   -> True
-1    -> True
if count: says no count, but 0 was a real value
if count is not None: says the count is 0

Write if items: for "not empty". When 0 or "" is a real answer, write if x is not None:.

4. A list as a default argument

A default value is made once, when def runs, not on every call. So a list default is shared by every call. Java has no default arguments, so this one is new.

def add_bad(item, bucket=[]):      # the [] is made ONCE, when def runs
    bucket.append(item)
    return bucket

print(add_bad("a"))
print(add_bad("b"))                # same list as the first call

def add(item, bucket=None):        # the fix: None, then a new list per call
    bucket = [] if bucket is None else bucket
    bucket.append(item)
    return bucket

print(add("a"))
print(add("b"))

Output:

['a']
['a', 'b']
['a']
['b']

Dataclasses have the same rule: dataclasses vs Java records.

5. zip stops at the shorter list

zip pairs up items from two lists. If one is shorter, the extra items are dropped with no error. A Java loop with an index would throw IndexOutOfBoundsException.

words = ["cat", "mat", "rat"]
scores = [2.0, 1.0]                # one score is missing

print(list(zip(words, scores)))    # rat is dropped, no error

try:
    list(zip(words, scores, strict=True))   # Python 3.10+
except ValueError as error:
    print("strict=True:", error)

Output:

[('cat', 2.0), ('mat', 1.0)]
strict=True: zip() argument 2 is shorter than argument 1

Use strict=True when both lists must match, for example texts and their embeddings.
