Exceptions: try, except, else, finally

Python exceptions work like Java's unchecked ones, with one extra: an else block. raise ... from keeps the cause, as Java's new X(msg, cause) does. These blocks run in your browser.

Which block runs when

def parse(text):
    print(f"parse({text!r})")
    try:
        number = int(text)
    except ValueError:
        print("  except:  not a number")
        return None
    else:
        print("  else:    no error, use", number)
        return number
    finally:
        print("  finally: always runs, even after return")

parse("42")
parse("forty-two")

Output:

parse('42')
  else:    no error, use 42
  finally: always runs, even after return
parse('forty-two')
  except:  not a number
  finally: always runs, even after return
  • else runs only when the try had no error. Java has no twin. Keep the try small, just the line that can fail, and put the rest in else.
  • finally runs even after return, as in Java.

First match wins

except blocks are tried top to bottom, and a parent catches its children. So put the child first.

def read(d, key):
    try:
        return d[key]
    except LookupError:            # parent of KeyError: matches first
        return "LookupError block"
    except KeyError:               # never reached
        return "KeyError block"

print(read({}, "model"))
print(" -> ".join(c.__name__ for c in KeyError.__mro__))   # the "extends" chain

Output:

LookupError block
KeyError -> LookupError -> Exception -> BaseException -> object

__mro__ is the class chain, like walking getSuperclass() in Java. except LookupError catches both KeyError and IndexError.

Your own errors, with the cause

A raw error says what broke, not what to do. Wrap it in your own error and keep the original with from. Java: new X(msg, cause).

class OllamaError(Exception): ...            # my base error
class OllamaDownError(OllamaError): ...      # (Parent) = extends

def ask(url):
    try:
        # stands in for httpx's ConnectTimeout (a TransportError): no network in this demo
        raise ConnectionRefusedError("nothing is listening on " + url)
    except OSError as error:
        raise OllamaDownError(f"no Ollama at {url}") from error   # keep the cause

try:
    ask("http://127.0.0.1:11434")
except OllamaError as error:                 # the parent catches every child
    print("caught:", type(error).__name__, "-", error)
    print("cause: ", type(error.__cause__).__name__, "-", error.__cause__)
    print("tip:    start Ollama: ollama serve")

Output:

caught: OllamaDownError - no Ollama at http://127.0.0.1:11434
cause:  ConnectionRefusedError - nothing is listening on http://127.0.0.1:11434
tip:    start Ollama: ollama serve
  • Callers catch OllamaError and get every child.
  • Catch at the edge, where you can do something useful: the chat loop prints the tip, while the function deep inside only raises.
  • No checked exceptions, so a docstring should list what a function raises.

Look first or just try

Three ways to read a key that may be missing:

settings = {"model": "qwen3:1.7b"}           # no "temperature" key

if "temperature" in settings:                # 1. look first (Java style)
    t = settings["temperature"]
else:
    t = 0.8
print("look first:", t)

try:                                         # 2. just try (usual Python style)
    t = settings["temperature"]
except KeyError:
    t = 0.8
print("just try:  ", t)

print("get:       ", settings.get("temperature", 0.8))   # 3. one call

Output:

look first: 0.8
just try:   0.8
get:        0.8

For dicts, get is the shortest. For files and network calls, just try: the file can vanish between the check and the use.
