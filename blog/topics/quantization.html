Quantization

A model is billions of numbers (weights). Quantization stores each one in fewer bits: the file gets smaller and faster to run, and a little less precise. Java view: double vs float vs short vs byte.

The formula

file size (GB) ≈ billions of weights × bits per weight ÷ 8
FormatBits per weightqwen3:4b sizeQuality
FP16168.0 GBoriginal
Q8_08.54.2 GBalmost the same
Q4_K_Mabout 52.5 GB (measured)small loss; Ollama's usual default

Rule of thumb: a bigger model at 4 bits usually beats a smaller model at 16.

RAM: the file is not the whole story

While running, the model also needs memory for the text it is reading (the KV cache, which grows with the context window) and some overhead. Measured: the 2.5 GB file used 3.2 GB in RAM, 28% more. So plan with file size × 1.3.

Speed

On a CPU, every new token reads all the weights from RAM once. A smaller file means less to read per token. Measured on a PC with no GPU:

ModelFileWriting speed
qwen3:4b2.5 GB7.1 tokens/s
qwen3:1.7b1.4 GB15.4 tokens/s

About half the file, about twice the speed.

The code

The size formula, then a toy version of the idea: each weight is stored as a small whole number between the lowest and highest weight, and turned back into a decimal when used.

def size_gb(billions_of_weights: float, bits_per_weight: float) -> float:
    return billions_of_weights * bits_per_weight / 8

for name, bits in [("FP16", 16), ("Q8_0", 8.5), ("Q4_K_M", 5)]:
    file_gb = size_gb(4.0, bits)
    print(f"qwen3:4b {name:7} {file_gb:4.1f} GB file, about {file_gb * 1.3:4.1f} GB in RAM")

# A toy version of the idea: store each weight as a small whole number.
weights = [0.82, -0.41, 0.07, -0.93, 0.55, 0.13]

def quantize(values: list[float], bits: int) -> tuple[list[int], list[float]]:
    steps = 2 ** bits - 1                                # 4 bits -> 15 steps between low and high
    low, high = min(values), max(values)
    step = (high - low) / steps
    codes = [round((value - low) / step) for value in values]   # what gets stored
    restored = [low + code * step for code in codes]            # what the model computes with
    return codes, restored

for bits in (8, 4, 2):
    codes, restored = quantize(weights, bits)
    worst = max(abs(a - b) for a, b in zip(weights, restored))
    print(f"{bits} bits: codes {codes}  worst error {worst:.3f}")

Output:

qwen3:4b FP16     8.0 GB file, about 10.4 GB in RAM
qwen3:4b Q8_0     4.2 GB file, about  5.5 GB in RAM
qwen3:4b Q4_K_M   2.5 GB file, about  3.2 GB in RAM
8 bits: codes [255, 76, 146, 0, 216, 154]  worst error 0.003
4 bits: codes [15, 4, 9, 0, 13, 9]  worst error 0.053
2 bits: codes [3, 1, 2, 0, 3, 2]  worst error 0.270

8 bits barely changes the weights; 2 bits moves one of them by 0.27. Real formats such as Q4_K_M work on small blocks of weights, each block with its own scale, so the error stays lower than in this toy.
