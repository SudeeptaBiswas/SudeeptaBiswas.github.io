AI · Sampling

Softmax and temperature

For every next token, the model gives each word in its vocabulary a raw score (a logit). Softmax turns those scores into odds that add up to 100%. Sampling then picks one token from those odds.

From scores to odds

softmax(score_i) = e^score_i / (e^score_1 + e^score_2 + ...)
WordScore (logit)e^scoreOdds
cat2.07.397.39 / 11.76 = 63%
mat1.02.722.72 / 11.76 = 23%
rat0.51.651.65 / 11.76 = 14%

e^x makes every value positive and stretches the gaps: a score 1 point higher means about 2.7 times the odds.

Temperature

Temperature is one division, score ÷ T, right before softmax:

TcatmatratFeels like
0.20.990.010.00almost greedy: safe, repeats
1.00.630.230.14the model's own odds
2.00.480.290.23flatter: rare words come up often

Interactive demo (needs JavaScript): a slider from T 0.2 to 3.0 that redraws the odds above.

T = 0 would divide by zero; Ollama treats it as greedy (always the top token). Measured with qwen3:1.7b, "Invent an unusual name for a pet cat", five calls: at T 0 it said Zephyrclaw five times; at T 0.6 it gave five different names.

top_k, top_p and the seed

  • top_k 2 keeps the 2 most likely tokens, then softmax runs again on them: cat 0.73, mat 0.27. Java/SQL view: ORDER BY prob DESC LIMIT 2.
  • top_p 0.8 keeps the most likely tokens until they cover 80%: cat (0.63), then mat (0.86), stop.
  • The pick is a weighted random choice, like a loot table. A seed makes it repeatable, like new Random(42) in a JUnit test.

The code

import math
import random

def softmax(scores: list[float], temperature: float = 1.0) -> list[float]:
    scaled = [score / temperature for score in scores]
    biggest = max(scaled)                                # subtract the max: same result, no overflow
    exps = [math.exp(score - biggest) for score in scaled]
    total = sum(exps)
    return [value / total for value in exps]

words = ["cat", "mat", "rat"]
scores = [2.0, 1.0, 0.5]                                 # logits the model gave

for temperature in [0.2, 1.0, 2.0]:
    odds = softmax(scores, temperature)
    print(f"T {temperature}: " + "  ".join(f"{w} {p:.2f}" for w, p in zip(words, odds)))

def top_p(words: list[str], odds: list[float], p: float) -> list[str]:
    kept, covered = [], 0.0
    for word, chance in sorted(zip(words, odds), key=lambda pair: pair[1], reverse=True):
        kept.append(word)
        covered += chance
        if covered >= p:                                 # enough of the odds covered: stop
            break
    return kept

print("top_p 0.8 keeps:", top_p(words, softmax(scores), 0.8))

rng = random.Random(42)                                  # seed: the same picks every run
picks = [rng.choices(words, weights=softmax(scores))[0] for _ in range(10)]
print("10 picks at T 1.0, seed 42:", picks)

Output:

T 1.0: cat 0.63  mat 0.23  rat 0.14

At T 1.0 the 10 picks are mostly cat, sometimes mat, once rat: close to the 63 / 23 / 14 odds. Run it again: the seed gives the same 10 picks.

Why it matters

  • JSON output, tool calls, an LLM judge: use T 0. One "creative" token breaks parsing.
  • Answers too samey or too wild? Fix the prompt first. The prompt sets the scores; temperature only reshapes them.
