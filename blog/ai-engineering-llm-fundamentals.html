AI Engineering: LLM Fundamentals

Started 5 November 2026 · In progress · Ollama, qwen3, nomic-embed-text

A large language model only guesses the next token. A loop turns those guesses into an answer, and your code does the rest: it keeps the chat history, sets the sampling options and finds related text. Everything here ran locally with Ollama on a PC, on the CPU only.

These are my study notes from my AI Engineering Lab, not production experience. This post is in progress: a section is added as each topic is finished. Timings were measured on my own PC and will differ on yours.

1. The big picture

2. Tokens and the context window

text → tokenizer → token ids → model → logits (one score per token in the vocabulary)
     → softmax (odds) → pick one → append to the text → repeat until "stop"
  • One token is about 4 characters of English, roughly ¾ of a word.
  • The model has no memory. A chatbot "remembers" because your code sends the whole history again on every call.
  • Everything must fit the context window: system message + history + question + answer. Too long? Drop the oldest messages and keep the system one. Too much data? That is what RAG is for.
  • Ollama's default window here was 4096 tokens. Past it, Ollama dropped old messages silently, with no error.
  • A model hallucinates because it picks what sounds right, not what is right.

3. Running models with Ollama

file size (GB) ≈ billions of weights × bits per weight ÷ 8
RAM needed     ≈ file size × 1.3          (KV cache + overhead)
time           = load (first call) + read the prompt + write the answer
Measured on my PC (CPU only)Result
qwen3:4b at Q4_K_M (about 5 bits per weight)2.5 GB on disk, 3.2 GB in RAM
Same model at FP168.0 GB
Writing speed, qwen3:4b vs qwen3:1.7bAbout 7 vs 15 tokens/s
Model load, first call vs second call9.4 s vs 0.009 s (kept in RAM for 5 minutes)
  • A CPU is slow because each new token reads all the weights from RAM once. Half the file size gives about twice the writing speed.
  • A bigger model at 4 bits usually beats a smaller one at full precision.
  • Trust ollama show, not the model's name.

4. The chat API

import httpx

body = {
    "model": "qwen3:1.7b",
    "messages": [
        {"role": "system", "content": "Answer in one sentence."},
        {"role": "user", "content": "What is a token?"},
    ],
    "stream": False,
    "think": False,                 # thinking tokens would eat num_predict
    "options": {"temperature": 0, "num_predict": 200},
}
reply = httpx.post("http://127.0.0.1:11434/api/chat", json=body, timeout=120).json()
print(reply["message"]["content"], reply["done_reason"])
  • Roles: system = your rules, user = the person, assistant = earlier answers.
  • done_reason: "length" means the answer hit num_predict and was cut off.
  • Thinking models spend most of their tokens thinking. Hiding the thinking doesn't skip it: once, all 60 allowed tokens went to hidden thinking and the answer was empty.
  • Streaming sends one JSON line per piece. The total time is the same, but the first words came after 0.13–0.64 s instead of 2.0–3.2 s.

5. Sampling

logits → ÷ temperature → softmax → cut the tail (top_k, top_p) → weighted random pick (seed)
OptionWhat it does
temperatureReshapes the odds. Low = safe and repetitive; high = bold. 0 acts greedy: the same answer 10 times out of 10
top_k, top_pRemove unlikely tokens before the pick
seedMakes the random pick repeatable, so tests stop being flaky
num_predictA hard cut, not "be short". Ask for short answers in the prompt

qwen3's defaults are temperature 0.6, top_k 20, top_p 0.95. For JSON output, tool calls or an LLM judge, use temperature 0: one "creative" token breaks parsing. Answers too samey? Fix the prompt first; it sets the odds, and temperature only reshapes them.

6. Embeddings and similarity

notes + question → POST /api/embed (one batched call) → vectors (768 numbers each)
  → cosine(question, each note) → sort best first → keep the top k

cosine(a, b) = dot(a, b) / (norm(a) × norm(b))
  • An embedding is a list of numbers. Similar meaning = vectors pointing the same way.
  • Use the same model for the notes and the question. Mixed models give nonsense scores and no error.
  • "Unrelated" is not 0 with real embeddings: cat vs invoice scored 0.40. Compare scores; never hard-code "0.5 = match".
  • Embeddings measure what a text is about, not whether it is positive: "I love this movie" vs "I hate this movie" scored 0.69.
  • Batch the call: 5 notes took 0.38–0.60 s in one call, against 1.34–1.92 s in five.

This search by meaning is the base of RAG, the next big part of the lab.

7. Check yourself

How does a chatbot remember if the model has no memory?

Your code sends the whole history again on every call.

Why is the second call much faster to start?

The model stays loaded in RAM for 5 minutes after a call.

Logits vs softmax?

Logits are raw scores. Softmax turns them into odds that add up to 100%.

top_p 0.8 on cat 0.63, mat 0.23, rat 0.14 keeps what?

cat and mat: 0.63 + 0.23 = 0.86, which reaches 0.8.

Why stream if the total time is the same?

The user starts reading while the model is still writing.

Cosine 1, 0 and -1 mean?

Same direction, unrelated (right angle), opposite.
